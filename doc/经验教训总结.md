# RuoYi-Flowable-Plus 开发陷阱与规范

## 一、PowerShell 编码陷阱（最致命）

### 1.1 `Set-Content -Encoding utf8` 会加 BOM

Windows PowerShell 5.1 的 `-Encoding utf8` 会写入 **UTF-8 with BOM**（3 字节 EF BB BF）。
Java 编译器、XML 解析器都不接受 BOM，导致：
- Java 文件 → `非法字符: '\ufeff'`
- XML 文件 → `前言中不允许有内容`

**正确做法：**
```powershell
# ❌ 不要用
Set-Content -Path file.java -Encoding utf8

# ✅ 用 .NET 方法写 UTF-8 without BOM
[System.IO.File]::WriteAllText($path, $content, [System.Text.UTF8Encoding]::new($false))
```

### 1.2 `$` 在双引号字符串中会被变量展开

PowerShell 的 `@"..."@` 和 `"..."` 中，`$variable` 会被展开。
JavaScript 中的 `$router`、`$refs`、`$modal` 会被 PowerShell 吃掉：
- `proxy.$router.back()` → `proxy..back()`
- `proxy.$refs.formRef` → `proxy..formRef`

**正确做法：**
```powershell
# ❌ 不要用双引号 here-string
@"... proxy.$refs.formRef ..."@

# ✅ 用单引号 here-string（$ 不会被展开）
@'... proxy.$refs.formRef ...'@
```

### 1.3 `Get-Content -Raw` 无编码参数会读成 ANSI

`Get-Content -Raw` 默认使用系统 ANSI 编码（中文 Windows 为 GBK）。
读取 **UTF-8 without BOM** 的文件时，当作 GBK 读取导致中文乱码。

**正确做法：**
```powershell
# ✅ 显式指定 UTF-8
$content = Get-Content $path -Encoding utf8 -Raw

# 更安全：用 .NET 按字节读取
$bytes = [System.IO.File]::ReadAllBytes($path)
$text = [System.Text.Encoding]::UTF8.GetString($bytes)
```

### 1.4 BOM 修复的正确姿势

不要用 `Substring(1)` 去修 BOM——`ReadAllText` 已经在内部处理了 BOM，
`Substring(1)` 会删掉真正的第一个文档字符（`<template>` 的 `<`、`import` 的 `i`）。

**正确做法：字节级截断：**
```powershell
$bytes = [System.IO.File]::ReadAllBytes($path)
if ($bytes[0] -eq 0xEF -and $bytes[1] -eq 0xBB -and $bytes[2] -eq 0xBF) {
    [System.IO.File]::WriteAllBytes($path, $bytes[3..($bytes.Length-1)])
}
```

### 1.5 终极方案：用 Python 或 .NET 写文件

PowerShell 编码问题太多。对于包含中文、`$` 的代码文件，直接用 .NET 方法：

```powershell
# ✅ 最安全的写法
$content = @'...内容...'@
[System.IO.File]::WriteAllText($path, $content, [System.Text.UTF8Encoding]::new($false))
```

## 二、后端 Java 陷阱

### 2.1 方法名一定要核实

不要凭记忆猜 API 方法名。不同 RuoYi 版本的方法名不同：
- `TableDataInfo.of(page)` → 实际是 `TableDataInfo.build(page)`

**做法：** 在项目里搜一下实际定义：
```bash
rg "public static.*TableDataInfo" --include "*.java"
```

### 2.2 检查实体类继承

`BaseEntity` 提供了 `createBy`, `createTime`, `updateBy`, `updateTime`。
如果业务表没有 `create_by/update_by` 列，实体类**不能继承 `BaseEntity`**，应直接实现 `Serializable`。

### 2.3 空 XML Mapper 文件可不建

用 MyBatis-Plus 标准方法（`selectById`, `selectList`, `insert`, `updateById`, `deleteBatchIds`），
**不需要创建 XML 映射文件**。创建了反而可能被 BOM 搞坏导致启动失败。

## 三、前端 Vue 陷阱

### 3.1 确认 Vue 版本（最严重的错误）

```bash
grep '"vue"' package.json
```
这个项目是 **Vue 2.6.12**，不是 Vue 3。

| 特性 | Vue 2（本项目） | Vue 3 |
|------|----------------|-------|
| 组件写法 | `export default { data, methods }` | `<script setup>` |
| 数据响应 | `data() { return {} }` | `ref()`, `reactive()` |
| DOM 引用 | `this.$refs.xxx` | `ref(null)` |
| 路由跳转 | `this.$router.push()` | `useRouter().push()` |
| 弹框绑定 | `:visible.sync` | `v-model` |
| 插槽作用域 | `slot-scope="scope"` | `#default="scope"` |
| 图标写法 | `icon="el-icon-search"` | `icon="Search"` |
| 对话框底部 | `<span slot="footer">` | `<template #footer>` |
| 模态框 | `this.$modal.msgSuccess()` | 无内置 |

### 3.2 Vue 2 中没有 `getCurrentInstance`

Vue 2 没有 `getCurrentInstance`，也不支持 `<script setup>`。
所有方法和数据都通过 `this` 在 `methods: {}` 中访问：
```javascript
export default {
  data() { return { list: [] } },
  created() { this.getList() },
  methods: {
    getList() { ... },
    handleSubmit() { this.$refs.formRef.validate(...) }
  }
}
```

### 3.3 Element UI 图标名称

Vue 2 项目用的是 Element UI（不是 Element Plus）：
- ❌ `icon="Search"`
- ✅ `icon="el-icon-search"`

常用：`el-icon-plus`, `el-icon-edit`, `el-icon-delete`, `el-icon-search`, `el-icon-refresh`, `el-icon-view`

## 四、添加代码前的检查清单

1. `package.json` → 检查 Vue 版本
2. `pom.xml` → 检查 Flowable 版本、模块依赖
3. 现有页面 → 找个同类页面看写法（Vue 2 Options API）
4. 后端方法 → `rg "public static.*build"` 确认方法名
5. **写文件用 `[System.IO.File]::WriteAllText`**，不用 `Set-Content`
6. **读文件加 `-Encoding utf8`**，别裸写 `Get-Content`
7. **带 `$` 的 JS 用单引号 here-string**，不用双引号
8. **XML 空 mapper 文件不创建**，不影响运行
