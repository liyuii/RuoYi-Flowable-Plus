# 检测流程（LIMS 样品检测）设计与实现方案

## 一、需求说明

### 1.1 业务目标
实现一个完整的样品检测审批流程，覆盖从报检申请到报告签发的全生命周期，使用 Flowable 工作流引擎驱动状态流转。

### 1.2 业务范围
本次只聚焦检测流程本身，不包括设备管理、库存管理、ECOA 等周边模块。

### 1.3 核心流程
`
报检申请 → 任务分配 → 结果录入（并行多实例）→ 自动QC判定 → 数据审核 → 报告签发 → 结束
                                                                      ↓（不合格）
                                                                  退回/复检
`

### 1.4 涉及的角色
| 角色 | 说明 | 对应系统用户 |
|------|------|------------|
| applicant（申请人/工艺员） | 发起报检 | sys_user |
| assigner（质量主管/分配人） | 分配检测任务到检测组 | sys_user |
| inspector（检测员） | 执行检测、录入结果 | sys_user 且属于某个检测组 |
| reviewer（审核人） | 审核检测结果 | sys_user |
| issuer（签发人） | 签发报告 | sys_user |

## 三、数据表设计

### 3.1 表总览（6 张表）

| 表名 | 用途 | 关键字段 |
|------|------|---------|
| lims_test_group | 检测组 | group_code（唯一编码） |
| lims_test_group_member | 检测组成员 | group_id, user_id（唯一联合） |
| lims_specification | 规格书 | spec_name, material_name, version |
| lims_spec_item | 规格书检测项目定义 | spec_id, item_name, spec_lower, spec_upper, test_group_id |
| lims_inspection | 报检单主表 | spec_id, batch_no, status, result_verdict |
| lims_test_item | 检测项目结果 | inspection_id, result_value, qc_result, test_group_id, assignee |

### 3.2 ER 关系

`	ext
lims_test_group
     1
     │
     N
lims_test_group_member ──→ sys_user

lims_specification
     1
     │
     N
lims_spec_item ──→ lims_test_group（一个检测项目属于一个检测组）

lims_inspection ──→ lims_specification（报检引用一本规格书）
     1
     │
     N
lims_test_item ──→ lims_test_group（检测时的组信息从规格书复制）
`

### 3.3 设计要点说明

1. **规格上下限快照**：lims_test_item.spec_lower / spec_upper 从 lims_spec_item 复制过来，不是关联查询。保证历史判定标准不变。
2. **businessKey 关联**：报检单不单独存 process_instance_id，用 usinessKey = ""inspection_"" + id 关联 Flowable 实例。
3. **状态字段分离**：lims_inspection.status 是业务状态，供页面展示；流程状态存在 Flowable 的 ACT_HI_PROCINST 表中。

## 四、Flowable 流程设计

### 4.1 流程定义（BPMN 2.0）

**流程 Key**：lims_sample_test

**环节列表**：

| 环节 | 类型 | 办理人 | 说明 |
|------|------|--------|------|
| 报检申请 | UserTask |  | 工艺员提交报检单，流程启动 |
| 任务分配 | ServiceTask | 自动执行 | JavaDelegate：根据检测组生成待办 |
| 结果录入 | UserTask | 并行多实例， | 每个检测项目一个实例 |
| QC判定 | ServiceTask | 自动执行 | JavaDelegate：自动比对规格上下限 |
| 数据审核 | UserTask | 固定角色（质量负责人） | 会签或单人审核 |
| 报告签发 | UserTask | 固定角色（授权签发人） | 终审，决定合格/不合格 |
| 不合格退回 | 排他网关 | — |  时退回 |
| 结束 | EndEvent | — | — |

### 4.2 转移方式

| 起点 | 终点 | 转移方式 | 条件 |
|------|------|---------|------|
| 报检申请 | 任务分配 | 顺序 | — |
| 任务分配 | 结果录入 | **发散（并行多实例）** | 按 testItems 列表展开 |
| 结果录入 | QC判定 | 顺序（汇聚） | nrOfCompletedInstances = nrOfInstances |
| QC判定 | 数据审核 | 顺序 | — |
| 数据审核 | 报告签发 | 顺序 | — |
| 报告签发 | 结束 | **排他网关** | 合格 → 正常结束 |
| 报告签发 | 报检申请 | **排他网关** | 不合格 → 退回 |

### 4.3 涉及 Flowable 概念

| 概念 | 使用位置 | 具体配置 |
|------|---------|---------|
| 并行多实例 | 结果录入环节 | loopCharacteristics.isSequential=false collection= elementVariable=testItem |
| 会签 | 数据审核环节（选做） | completionCondition= |
| 排他网关 | 报告签发 → 结束/退回 | 条件： 和  |
| 边界定时事件 | 结果录入环节（选做） | PT24H，超时后触发提醒 |
| 服务任务 | 任务分配、QC判定 | JavaDelegate 实现 |

### 4.4 流程变量设计

| 变量名 | 类型 | 赋值时机 | 用途 |
|--------|------|---------|------|
| inspectionId | Long | 启动流程时 | 关联报检单 |
| testItems | List | 任务分配 ServiceTask | 多实例的集合源 |
| testItem | Object | 多实例循环 | 当前检测项数据 |
| resultVerdict | String | 报告签发 Task | 终审结论（P/F） |

## 七、面试可提炼要点

1. **"快照设计"**：检测项的规格上下限从规格书复制而不是关联，防止历史判标不准。
2. **"businessKey 关联"**：不存冗余的 process_instance_id，用 ""inspection_"" + id 做关联。
3. **"并行多实例展开"**：按检测项目数量动态创建 N 个并行任务，不是预先画死的。
4. **"ServiceTask 自动分配"**：任务分配环节通过 JavaDelegate 自动设置 assignee，不用人工干预。
5. **"状态分离"**：业务状态存在业务表、流程状态存在 Flowable 引擎表，互不混淆。
